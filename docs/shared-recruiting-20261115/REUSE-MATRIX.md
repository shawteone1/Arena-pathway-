# Soccer Center → shared AP recruiting reuse matrix

Inspected before implementation. AP baseline: `1ea380462c1811a9ba3b2bbc7a6a5e1729b8bab8`; isolated branch `codex/shared-recruiting-20261115`. Latest imported SC source rechecked through GitHub: `11de067414e63c5d3e3e221dfc14cc026dfbd8d0`. SC is React/TypeScript with authenticated services; AP is Node-rendered HTML and browser ES modules with local storage. Direct React mounting would add a second runtime and duplicate service boundaries, so the shared behavior is ported, not the SC application/backend.

| Actual SC component/service | AP baseline equivalent | Decision and source-derived behavior | Shared contract / adapter | Compatibility and privacy |
|---|---|---|---|---|
| `RecruitingTab.tsx`, programs/coaches interfaces | `college-research.js` | **Adapt/port** institution/filter/expand-program hierarchy, programs remain visible when coaches withheld, official staff provenance, saved/camp/showcase/draft views | Sport-keyed program/coach/opportunity adapters; existing reviewed program/team assignments | Never use soccer records as another sport; missing contacts explicitly withheld. Public research remains independent of athlete creation. |
| `coach-profile-fields.ts` | Coarse `recruiting.visibility` checkboxes | **Port** canonical field keys, groups and explicit allowlist | `recruiting-fields.js`; exact approved field list with legacy visibility adapter | AP retains stricter empty defaults (SC preselects recommended fields after loading); photo and school consent independent; unknown keys cannot expose arbitrary profile data. Existing visibility preserved without destructive migration. |
| `coach-sharing.ts` `filterCoachProfile` | Inline/legacy snapshot assembly | **Reuse (JS port)** the allowlisted FIELD_OUTPUTS filtering function | One canonical `CoachProjection` subset shared by preview and renderer | No full athlete object reaches renderer; no private notes, birth data or unrelated module data. Existing record/event/media references retained. |
| `coach-projection.ts`, selected-match aggregation | `competition-records.js` + inline builder card | **Port/adapt** select owned competition IDs before aggregation, no profile-total fallback, explicit media/event sets | `recruiting-profile.js` and sport aggregation/measurement config | Practices and other-athlete media excluded; distinguish unavailable metrics from zero; only selected appearances, no schedule database copy. |
| `ProfileBuilder.tsx` | Builder's academic/about form | **Port/adapt** same-athlete optional introduction, academics, achievements, college goals and graduation fields | Existing athlete root fields plus additive optional fields; no new identity store | Prefill existing fields; save only edited profile fields; edits invalidate local approval. Legacy drafts/saves/extensions retained. |
| `CoachShareTab.tsx` | Builder selection/approval handlers | **Port/adapt** grouped field selection, explicit empty sets, review before approval, revision/revocation | Existing `recruiting` preferences, recordIds/eventRefs/highlightIds + approvedFields | Preserve AP parent/age16/rules gate. Browser-local approval only; no token/link/email delivery implementation. |
| `CoachProfileCard.tsx` | Inline `drawCard()` | **Port** recognizable identity/photo header, About Me, college goals, school/academic blocks, selected-stat grid with coverage, achievements, playable highlights, appearances | Standalone shared `coach-card.js` consumes only canonical projection and scoped media resolver | AP brand; no fabricated photo/results; selected local photo/video is owner preview, not protected external media sharing. |
| `CoachProfilePreview.tsx` | Builder step3 | **Adapt** same strict card projection for owner preview | Same projection/renderer in all four sports | No alternate summary renderer or coach-access endpoint. |
| SC saved schools, camps/showcases, drafts services | `profile.saved`, `recruiting.outreachDraft`, legacy checklist/notes | **Preserve/adapt** interface hierarchy over existing references | Existing catalog IDs and profile preferences | No duplicate saved-school/event database; preserve private old drafts/checklist. |
| `ParentRecruitingHub.tsx` | `/recruiting` entry + athlete Recruiting tab | **Adapt** research-first, continue with existing athlete, predictable three-stage path | Same public route, one builder/card, sport chosen through adapter | Recruiting remains optional; no profile required for school research. Retain legacy notes/checklist, but retire the inline athlete-page builder. Every active builder/card entry uses the same `/recruiting` journey. |
| SC auth, token stores, media proxy, outreach POST handlers | AP unconnected capabilities | **Do not import/activate** | Future authorized infrastructure gate only | No production auth, external sharing, coach posting, payment/verification or SC mutations. |

One platform implementation in AP will serve Lacrosse, Basketball, Volleyball and Swimming. Soccer Center's deployed runtime remains unchanged; this does not claim that both deployed products already import one npm package or share a production backend. The extracted field/projection/card contracts are reusable foundations, not a second recruiting application.
